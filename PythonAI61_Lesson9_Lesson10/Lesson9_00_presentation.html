Регресія з однією змінною

Перший справжній Machine Learning: даєте приклади → fit() → predict(). Почнемо з годин навчання та ціни квартири — без зайвих термінів.

  • Сформулювати регресійну задачу як передбачення числової цілі
  • Пояснити модель лінійної регресії з однією ознакою
  • Побудувати базовий workflow: dataset → split → fit → predict
  • Виконати офіційні завдання 1–2 та аналоги 1.1–2.1 на датасеті diabetes
Перед початком
  • Train vs test на рівні ідеї
  • MAE/MSE інтуїтивно
  • Не готувати y за допомогою майбутнього X
Після пари ви можете
  • Побудувати лінійну регресію з однією ознакою
  • Пояснити slope/intercept
  • Показати прогноз на hold-out точках

Підказка: терміни з пунктирним підкресленням — наведіть курсор (або тапніть), щоб побачити коротке пояснення. Словник уже вбудований у цей файл: терміни з пунктиром показують підказку без журналу й без інтернету.

Старт: що таке Machine Learning простими словами

теорія · v2

До цього моменту ми в основному описували дані: середнє, графік, таблиця. Сьогодні змінюємо питання — не «що вже було», а «що буде далі».

Machine Learning — це коли ви показуєте компʼютеру приклади, а він сам знаходить закономірність. Потім ви питаєте: «а що буде для нового випадку?»

1. ДаніПари «ознака X → відповідь y»
2. fit()Модель підбирає параметри
3. predict()Прогноз для нового X
Коротко

Регресія — коли відповідь число: оцінка на тесті, ціна квартири, час доставки. Не «котик чи собачка», а «скільки».

Приклад 1 · години навчання → оцінка

теорія · v2

Три кроки fit/predict з попереднього блоку — абстракція. Закріпимо їх на задачі, яку легко уявити без формул.

Найпростіша регресія: скільки годин ви вчилися — і яка оцінка вийшла.

from sklearn.linear_model import LinearRegression

# X — години навчання
X = [[1], [2], [3], [4], [5]]
# y — оцінка
y = [50, 60, 70, 80, 90]

model = LinearRegression()
model.fit(X, y)
result = model.predict([[6]])
print(result)  # -> [100.]
# -> приблизно 100
assert abs(result[0] - 100.0) < 1.0

Модель сама знаходить залежність між X та y. Ви не писали формулу руками — sklearn підібрав її під ваші приклади.

Зверніть увагу

X має бути двовимірним: [[1], [2], …], а не [1, 2, …]. Так працює sklearn.

Приклад 2 · площа квартири → ціна

теорія · v2

Код майже той самий — змінюється лише сенс стовпчиків. Якщо ланцюжок «дані → fit → predict» зрозумілий на оцінках, перевірте себе на іншій темі.

Той самий підхід — інша задача. Дали приклади, запитали прогноз:

from sklearn.linear_model import LinearRegression

# Площа квартири, м²
X = [[30], [40], [50], [60], [70]]
# Ціна, $
y = [40000, 50000, 60000, 70000, 80000]

model = LinearRegression()
model.fit(X, y)
price = model.predict([[55]])
print(price)  # -> [65000.]
# -> приблизно 65000
assert abs(price[0] - 65000.0) < 500.0
  • 30 м² → $40 000
  • 40 м² → $50 000
  • 50 м² → $60 000
  • 55 м² → ? модель відповідає ≈ $65 000
Коротко

Ви не програмували «+1000 за м²». Модель сама знайшла схожу закономірність у даних.

Приклад 3 · відстань → час доставки

теорія · v2

Ще один «бытовий» приклад — щоб переконатися: схема не привʼязана до грошей чи оцінок. Знову одне число на вході, одне на виході.

Чим далі адреса, тим більше хвилин їде курʼєр:

from sklearn.linear_model import LinearRegression

# X — відстань, км
X = [[1], [2], [3], [4], [5]]
# y — час доставки, хв
y = [15, 25, 35, 45, 55]

model = LinearRegression()
model.fit(X, y)
mins = model.predict([[3.5]])
print(mins)  # -> [30.]
# -> приблизно 30 хв на 3.5 км
assert abs(mins[0] - 30.0) < 1.0
  • 1 км → 15 хв
  • 3 км → 35 хв
  • 3.5 км → ? модель відповідає ≈ 30 хв (між сусідніми точками)
Коротко

Ознака X і ціль y можуть бути чим завгодно — головне, що y — число, а не категорія.

Приклад 4 · що саме вивчила модель

теорія · v2

Ми вже бачили predict() — модель відповідає числом. Тепер заглянемо «під капот»: які саме параметри вона підібрала під приклад з квартирами.

Після fit() можна подивитися параметри — це і є «формула», яку знайшла модель:

from sklearn.linear_model import LinearRegression

X = [[30], [40], [50], [60], [70]]
y = [40000, 50000, 60000, 70000, 80000]
model = LinearRegression().fit(X, y)

print(model.coef_)       # -> [1000.]
print(model.intercept_)  # -> [10000.]
# -> price ≈ 1000 * area + 10000

Тобто модель фактично знайшла правило приблизно:

price = 1000 × area + 10000

coef_

На скільки змінюється y, коли x зростає на 1 (тут +$1000 за +1 м²).

intercept_

Базове значення при x = 0 (тут $10 000 — умовна «база»).

Приклад 5 · прогноз за формулою вручну

теорія · v2

Коли ви знаєте coef_ і intercept_, прогноз — це звичайна арифметика. Перевірка вручну допомагає зрозуміти, що робить predict() «за кадром».

Для квартири 55 м² з попереднього прикладу:

from sklearn.linear_model import LinearRegression

X = [[30], [40], [50], [60], [70]]
y = [40000, 50000, 60000, 70000, 80000]
model = LinearRegression().fit(X, y)

area = 55
price_manual = model.coef_[0] * area + model.intercept_
price_sklearn = model.predict([[area]])[0]
print(round(price_manual), round(price_sklearn))  # -> 65000 65000
assert abs(price_manual - price_sklearn) < 1.0
Зверніть увагу

predict([[55]]) і «coef × 55 + intercept» дають те саме — sklearn просто рахує формулу за вас.

Регресія: передбачаємо число

теорія · v2

Три приклади вище — уже регресія, просто ми ще не давали цьому імені. Зафіксуємо термін і відділимо від задач, де відповідь — не число.

У попередніх модулях ви описували дані (середнє, графік, таблиця). Тут мета інша: передбачити число для нового обʼєкта.

Тип задачіЩо передбачаємоПриклад
КласифікаціяКатегоріяспам / не спам
РегресіяЧислоціна, оцінка, час
Зверніть увагу

Якщо відповідь «скільки» — це регресія. Якщо «який клас» — класифікація (буде пізніше).

Ціль — число: де регресія закінчується і починається класифікація

додатковий матеріал

Регресія має сенс лише коли y — вимірюване число з порядком і відстанню: ціна, температура, хвилини очікування. Якщо «1 / 2 / 3» — це пріоритет тікета, відстань між класами не є метрами: модель може передбачити 1.7, а бізнес чекає мітку.

  • Числова шкала: 200 і 400 відрізняються вдвічі; класи «low/high» — ні.
  • Порядок без відстані (бронза / срібло / золото) ближчий до ординальної класифікації, ніж до MSE.
  • Leakage: не беріть у X колонку, яку рахують після цілі (фінальний рахунок, «ціна після ремонту»).
Часта пастка

Закодувати категорію як 0/1/2 і годувати LinearRegression — це не «майже регресія». Прогноз 1.4 не є класом. Для міток потрібна класифікація (пара 14: LogisticRegression).

Ціле n_replies може бути регресією (рахуємо штуки) або класифікацією (біни вже зафіксовані продуктом). Різниця не в dtype int vs float, а в тому, чи відстань |3−1| має сенс як «удвічі більше відповідей». Якщо бізнес діє однаково на 4 і на 40 replies — ви вже в класифікації, навіть коли колонка int.

Зверніть увагу: LinearRegression завжди віддасть float. Округлення 1.7 до «класу 2» не робить задачу регресією — це зламана класифікація без predict_proba.

from sklearn.dummy import DummyRegressor, DummyClassifier
print(DummyRegressor().predict, DummyClassifier().predict_proba)

Місток · від прикладів до датасету diabetes

теорія · v2

Години, квартири й доставка — маленькі таблиці, щоб зрозуміти fit і predict. Далі — той самий sklearn-код, але сотні рядків і медична ціль замість оцінки.

У завданні 1 ви візьмете load_diabetes(): багато пацієнтів, одна ознака (наприклад BMI), ціль — рівень захворювання. Ланцюжок не змінюється:

Було5 рядків «години → оцінка»
Стало442 рядки, одна колонка X, числова y
Те самеreshape(-1,1) → fit → predict
Зверніть увагу

Більше даних не означає «інший ML». Змінюється масштаб, не схема.

Завдання 1 + 1.1 + 1.2 · LinearRegression на одній ознаці diabetes

практика ITSTEP · база
База · у вікні 80 хв

Responsible AI. Leakage і threshold: одна метрика не описує шкоду. Покажіть обмеження користувачеві.

Приклад · 1 · RUNNABLE

1 · офіційне завдання. Завантажте load_diabetes(), візьміть одну ознаку (наприклад, індекс 2), зробіть train/test split 80/20, навчіть LinearRegression і виведіть перші 10 реальних і передбачених значень поруч.

Розбір і рекомендоване рішення — натисніть, щоб побачити
from sklearn.datasets import load_diabetes
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import train_test_split

X, y = load_diabetes(return_X_y=True)
x = X[:, 2].reshape(-1, 1)

x_train, x_test, y_train, y_test = train_test_split(x, y, test_size=0.2, random_state=42)
model = LinearRegression().fit(x_train, y_train)
y_pred = model.predict(x_test)

for real, pred in zip(y_test[:10], y_pred[:10]):
    print(f"{real:8.2f}  →  {pred:8.2f}")
assert x_test.shape == (89, 1)          # 20% від 442 рядків
assert y_pred.shape == y_test.shape     # прогноз на кожен тестовий приклад

Ключове. reshape(-1, 1) обов’язковий: sklearn чекає 2D X навіть для однієї ознаки. random_state=42 фіксує розбиття, щоб числа були відтворювані.

Практика · 1.1

1.1 · зробіть за аналогією. Повторіть експеримент для іншої одиночної ознаки з того самого датасету або для синтетичних даних make_regression(..., n_features=1). Додайте короткий висновок: чи схожі коефіцієнти моделі на інтуїтивний звʼязок між ознакою і ціллю.

Розбір і рекомендоване рішення 1.1 — натисніть, щоб побачити
from sklearn.datasets import load_diabetes
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import train_test_split

X, y = load_diabetes(return_X_y=True)
x = X[:, 8].reshape(-1, 1)          # інша одиночна ознака
x_tr, x_te, y_tr, y_te = train_test_split(x, y, test_size=0.2, random_state=42)
m = LinearRegression().fit(x_tr, y_tr)
print("coef, intercept:", round(m.coef_[0], 1), round(m.intercept_, 1))
for r, p in list(zip(y_te, m.predict(x_te)))[:10]:
    print(round(r, 1), "->", round(p, 1))
# -> coef, intercept: 901.2 152.6
# -> 219.0 -> 181.9
# -> 70.0 -> 132.3
# -> 202.0 -> 228.8
# -> 230.0 -> 241.5
# -> 111.0 -> 148.0
# -> 84.0 -> 133.4
# -> 242.0 -> 183.0
Практика · 1.2

1.2 · складніший крок. Візьміть дві ознаки з diabetes замість однієї, навчіть LinearRegression і виведіть таблицю «ознака → коефіцієнт». Поясніть, чому знак коефіцієнта може відрізнятися від знаку кореляції ознаки з ціллю.

Розбір і рекомендоване рішення 1.2 — натисніть, щоб побачити
import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import train_test_split

X, y = load_diabetes(return_X_y=True, as_frame=True)
cols = ["bmi", "bp"]
X2 = X[cols]
x_tr, x_te, y_tr, y_te = train_test_split(X2, y, test_size=0.2, random_state=42)
m = LinearRegression().fit(x_tr, y_tr)
for c, w in zip(cols, m.coef_):
    print(f"{c}: coef={w:.1f}  corr={np.corrcoef(X[c], y)[0,1]:.2f}")
# -> bmi: coef=839.5  corr=0.59
# -> bp: coef=393.5  corr=0.44

Ключове. У множинній регресії коефіцієнт показує вплив ознаки за фіксованих інших; тому він може не збігатися з простою кореляцією, якщо ознаки корельовані між собою.

Пряма на графіку — найпростіша модель

теорія · v2

У прикладах з квартирами ми вже мали «+1000 за м²» — це і є нахил прямої. Тепер додамо загальні позначення, які зустрінете в sklearn і в завданні 2.

Лінійна регресія малює пряму через хмару точок. Формула: прогноз = w × x + b.

w (coef_)

Нахил: +1 до x → +w до прогнозу.

b (intercept_)

Зсув: значення при x = 0.

ŷ

Прогноз моделі, не реальне y.

Коротко

Модель не «запамʼятовує» кожну точку — вона знаходить одну пряму, яка найкраще підходить усім прикладам.

Приклад 6 · scatter і пряма на одному графіку

теорія · v2

Числа в таблиці зрозумілі, але на парі 9 нам потрібен ще й графік. Повернемось до «годин → оцінка» і намалюємо точки разом із лінією моделі — так само, як у завданні 2.

import matplotlib.pyplot as plt
from sklearn.linear_model import LinearRegression

hours = [[1], [2], [3], [4], [5]]
grades = [50, 60, 70, 80, 90]
model = LinearRegression().fit(hours, grades)
line_x = [[1], [6]]
line_y = model.predict(line_x)

fig, ax = plt.subplots(figsize=(6, 4))
ax.scatter([1, 2, 3, 4, 5], grades, label="дані")
ax.plot([1, 6], line_y, color="C1", label="пряма")
ax.set_xlabel("години навчання")
ax.set_ylabel("оцінка")
ax.legend()
# -> точки + лінія на одному полотні
assert abs(line_y[1] - 100.0) < 1.0  # 6 год → ~100
Коротко

Scatter показує факти, лінія — модель. Пряма не проходить через кожну точку — вона «найкраще підходить» усім одразу.

Пояснення · залишок (residual) простими словами

теорія · v2

На графіку ви вже бачили точки і пряму — не кожна точка лежить на лінії. Різниця «реальне y мінус прогноз» і є залишок; саме їх усереднюють метрики на наступній парі.

Для одного прикладу:

  • Реальна оцінка: 70
  • Модель сказала: 68
  • Залишок: 70 − 68 = +2 (модель занизила на 2 бали)

MAE і MSE на парі 10 — це способи звести багато таких різниць до одного числа.

Коротко

Residual = помилка на одному рядку. Метрика = як усереднити помилки по всьому test.

Одна ознака — один стовпчик X

теорія · v2

Іграшкові приклади мали по одному стовпчику X — тепер те саме на справжньому датасеті diabetes, який чекає в завданні 1.

«Регресія з однією змінною» — це коли ви берете один стовпчик як ознаку. Наприклад, лише BMI з датасету diabetes.

from sklearn.datasets import load_diabetes

X, y = load_diabetes(return_X_y=True)
x = X[:, 2].reshape(-1, 1)  # одна ознака → форма (442, 1)
print(x.shape)  # -> (442, 1)
Часта пастка

reshape(-1, 1) обовʼязковий: sklearn чекає таблицю, навіть якщо колонка одна.

Пряма — модель припущення, а не форма хмари

додатковий матеріал

Формула ŷ = w·x + b каже: зміна x на 1 завжди додає той самий w до прогнозу. Якщо scatter — дуга, сходинка або дві хмари, пряма все одно намалюється: це компроміс MSE, не «закон».

  • w має сенс лише в одиницях ознаки: «+1 до BMI» ≠ «+1 до віку в днях».
  • Залишки (residual = y − ŷ) мають виглядати як шум. Систематична дуга в залишках — лінійність не тримається.
  • Точка з екстремальним x тягне нахил сильніше, ніж точка біля середнього: важіль (leverage).
Зверніть увагу

Високий нахил на train не доводить причинність. Це асоціація в цій вибірці. Інша ознака (пара 9, інший стовпець diabetes) може дати зовсім інший w при тій самій цілі.

OLS знаходить пряму з мінімальною сумою квадратів, навіть коли істинна залежність — злам. Важіль точки на краю x більший: одна аномалія BMI тягне w сильніше за десяток точок біля середнього.

Зверніть увагу: високий |w| на train не означає, що ознака «важлива» в іншій шкалі. Вік у днях дасть крихітний w порівняно з віком у роках на тій самій цілі — це одиниці, не сила звʼязку.

Одна ознака — колонка для всіх рядків, уже 2D

додатковий матеріал

«Регресія з однією змінною» означає одну колонку X на всі спостереження, не один рядок таблиці. X[:, 2] з load_diabetes має форму (n,) — sklearn відхилить її в fit, поки не стане (n, 1).

  • reshape(-1, 1) або df[['bmi']] (DataFrame уже 2D) — два безпечні шляхи.
  • Часто плутають: один приклад (рядок) vs одна ознака (стовпець).
  • У load_diabetes ознаки вже центровані й масштабовані в датасеті: «сирий BMI» ви з колонки не прочитаєте.
Часта пастка

Взяти X[2] замість X[:, 2] — це третій рядок усіх ознак, не третя ознака всіх рядків. Форма буде (n_features,), і сенс моделі зламається ще до метрик.

Workflow: split → fit → predict

теорія · v2

Один стовпчик X — це ще не повний ML-процес. Перед тим як оцінювати модель, дані ділять на train і test — так перевіряють прогноз на «нових» рядках.

Workflow: split → fit на train → predict на test → baseline

додатковий матеріал

Чесний сценарій: спочатку відкласти test, потім fit лише на train. Якщо fit бачить усі рядки, метрика на «тесті» більше не є іспитом — це leakage через памʼять точок.

  • train_test_split(..., test_size=0.2, random_state=42) фіксує поділ; без random_state сусід отримає інші числа.
  • До святкування R² порівняйте з DummyRegressor(strategy='mean') на тому ж test.
  • Масштабувати ознаку (якщо робите) — після split, статистиками train. Інакше test «підказує» mean/std.
Зверніть увагу

LinearRegression не має епох: один fit — готовий OLS. Повторний fit на тих самих даних просто перезапише coef_, а не «довчиться».

LinearRegression.fit ідемпотентний відносно RNG: повторний fit на тих самих X,y дає ті самі coef_. Це не «довчання». SGDRegressor навпаки залежить від max_iter і eta0. Зверніть увагу: score() регресора — завжди R², навіть коли в звіті ви дивитеся MAE.

Додатково: інтерпретація generalization через train/test

додатковий матеріал

Корисно подивитися, як виглядають прогнози на train і test: різниця в якості підказує, чи модель краще узагальнює, а чи “підганяється”. За потреби можна обчислити MAE для інтуїтивного порівняння.

Узагальнення видно в парі чисел, не в «гарна пряма на train». Порахуйте MAE (або R²) на train і на test: якщо train помітно кращий — модель підлаштувалась під знайомі точки.

Додатково: як вибір ознаки впливає на форму звʼязку

Відповідальний AI: навчання з учителем

додатковий матеріал

Модель ухвалює рішення про людей — і її помилка має ціну, різну в кожен бік. Три правила:

  • Ніякого витоку. train_test_split — до будь-якого fit, масштабування чи підбору ознак.
  • Одна метрика не описує шкоду. Разом із R² / accuracy показуйте, де саме модель помиляється і кого це зачіпає.
  • Поріг — це рішення. Зсув порога класифікації змінює баланс хибних тривог і пропусків; його обирає людина під ціну помилки.

Домашнє / stretch

додатковий матеріал

Необовʼязково для заліку пари, але якщо час дозволяє — бажано ознайомитись.

Тема. DummyRegressor(mean) як baseline.

Що зробити

  1. Візьміть ту саму ознаку й ціль, що на парі (або diabetes з sklearn).
  2. Зробіть train_test_split(..., random_state=42).
  3. Навчіть DummyRegressor(strategy='mean') лише на train.
  4. Надрукуйте MAE або R² на test і порівняйте одним рядком з вашою LinearRegression.

Що здати. Скрипт stretch_pair09.py з двома метриками в print.

Готово, коли. Dummy навчений після split; метрика на test, не на train.

Рубрика (100)
  • train_test_split(random_state=42), DummyRegressor навчений лише на train — 30
  • метрика (MAE або R²) на test для обох моделей — 35
  • рядок порівняння: наскільки LinearRegression краща за baseline — 25
  • висновок чесний, навіть якщо модель не краща за середнє — 10
