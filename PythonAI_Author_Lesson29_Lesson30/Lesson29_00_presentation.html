RNN, LSTM і seq-to-seq

сьогодні

Речення — послідовність, не мішок слів. RNN передає стан з кроку на крок. LSTM окремо вирішує, що памʼятати, що забути і що видати. Seq-to-seq має кодер послідовності і декодер іншої послідовності.

На кроці t вхід — вектор поточного токена плюс стан з кроку t−1. Вихід кроку і новий стан задає одна й та сама мережа з тими самими вагами.

Довга послідовність у простої RNN гасить ранні токени: нахил до них стає малим. LSTM тримає окрему памʼять, яку не обовʼязково перезаписувати щокроку.

У seq-to-seq кодер стискає вхід у стан. Декодер із цього стану пише вихідні токени по одному. Довжини входу і виходу можуть відрізнятися.

Що задаємо ми

Розмір стану, словник індексів, чи це RNN чи LSTM.

Що спільне на всіх кроках

Ваги. Міняється стан і токен.

Де зникає початок фрази

У довгій простій RNN. LSTM для цього і тримає окрему стрічку памʼяті.

Перший обов'язковий крок перед RNN — перетворити токени на індекси. Для цього збираємо спільний словник.

    ("where is my order", "check the orders page"),

Padding і max length: одна форма для batch

теорія

Глибина пояснення

теорія

Глибина пояснення

Seq2seq + attention на маленькому словнику

додатковий матеріал

Глибина пояснення

Каркас encoder-decoder без уваги лише «перекидає» останній стан. Attention дозволяє декодеру дивитися на всі кроки енкодера. Нижче — повністю локальний приклад.

Каркас encoder-decoder без уваги лише «перекидає» останній стан. Attention дозволяє декодеру дивитися на всі кроки енкодера. Нижче — повністю локальний приклад.

import torch
from torch import nn

torch.manual_seed(0)
vocab, d, steps = 11, 8, 4
src = torch.randint(1, vocab, (2, steps))
emb = nn.Embedding(vocab, d)
enc = nn.GRU(d, d, batch_first=True)
enc_out, _ = enc(emb(src))  # (B, T, d)
query = enc_out[:, -1:, :]  # (B, 1, d)
scores = torch.bmm(query, enc_out.transpose(1, 2))
weights = torch.softmax(scores, dim=-1)
context = torch.bmm(weights, enc_out)
assert context.shape == (2, 1, d)
print(weights.shape, round(float(weights[0].sum()), 3))
# -> torch.Size([2, 1, 4]) 1.0

Навіщо цей шар

Новий акцент: Нулі padding не ігноруються самі: вони псують hidden state.

ignore_index у loss ховає pad від градієнта по логітах, але не вимикає кроки RNN на нульових токенах. Якщо ви не пакуєте послідовність і не маскуєте, фінальний state «пам'ятає» хвости нулів.

Лекція вже кодує QA-пари, робить словник і padding, ганяє tiny nn.RNN та CrossEntropy(ignore_index=0); Transformer лише як місток.

Поняття

pack_padded_sequence (або mask у LSTM) пропускає лише справжню довжину. Gradient clipping обрізає норму, коли розгорнутий граф вибухає — це інший важіль, ніж pad. У Transformer pad ріжеться attention mask; у RNN це треба зробити явно. Інакше батч з різною довжиною вчить артефакт пакування.

"""Runnable demo for pair 29: Нулі padding не ігноруються самі: вони псують hidden state."""

from __future__ import annotations

try:
    import math

    def last_hidden(xs, w=0.6):
        h = 0.0
        for x in xs:
            h = math.tanh(w * h + x)
        return h

    real = [0.8, 0.5, 0.2]
    padded = real + [0.0, 0.0]
    print('real', last_hidden(real), 'padded', last_hidden(padded))
    assert abs(last_hidden(real) - last_hidden(padded)) > 1e-6
    assert last_hidden(padded[:3]) == last_hidden(real)
    grad = (3.0, 4.0)
    norm = math.hypot(*grad)
    scale = min(1.0, 1.0 / norm)
    clipped_norm = math.hypot(grad[0] * scale, grad[1] * scale)
    print('clipped_norm', clipped_norm)
    assert clipped_norm <= 1.0 + 1e-9
except ModuleNotFoundError as exc:
    print('skip_missing_dep', getattr(exc, 'name', None) or exc)

Результат
