За Жероном · що таке кластеризація і де її застосовують

книжка

Кластеризація — це задача знайти схожі приклади і розкласти їх по кластерах, тобто групах схожих між собою прикладів.

Як і в класифікації, кожен приклад потрапляє в якусь групу. Але кластеризація — задача без учителя: міток немає, і алгоритм сам має зрозуміти, як групувати. Книжка показує це на наборі iris. Якщо сорти відомі, це звичайна класифікація. Якщо мітки прибрати, класифікатор уже не застосувати — тут і потрібна кластеризація. Одну групу видно й оком; що друга насправді складається з двох підгруп, уже не так очевидно. Алгоритми використовують усі ознаки одразу і справляються: суміш гаусіан помиляється лише на 5 прикладах із 150.

За Жероном · k-means на пʼяти згустках

книжка

На наборі без міток чітко видно пʼять згустків. k-means — простий алгоритм, який кластеризує такі дані дуже швидко, часто за кілька ітерацій.

Трохи історії з книжки: алгоритм запропонував Стюарт Ллойд у Bell Labs 1957 року, але за межами компанії його опублікували лише 1982-го. 1965 року Едвард Форджі опублікував практично той самий алгоритм, тому його іноді називають алгоритмом Ллойда — Форджі.

Дані без міток і межі кластерів k-means

Ліворуч — самі дані. Праворуч — пʼять областей; хрестик позначає центроїд кожного кластера. У книжці цьому відповідає рис. 8-2 і 8-3. Графік побудовано кодом нижче, а не взято з книжки.

import numpy as np
import matplotlib.pyplot as plt
from sklearn.cluster import KMeans
from sklearn.datasets import make_blobs

centers = np.array([[0.2, 2.3], [-1.5, 2.3], [-2.8, 1.8], [-2.8, 2.8], [-2.8, 1.3]])
spread = np.array([0.4, 0.3, 0.1, 0.1, 0.1])
X, y = make_blobs(n_samples=2000, centers=centers, cluster_std=spread, random_state=7)   # y не використовуємо

def plot_regions(model, X, ax, title):
    xx, yy = np.meshgrid(np.linspace(-3.6, 1.6, 400), np.linspace(0.4, 3.4, 300))
    zones = model.predict(np.c_[xx.ravel(), yy.ravel()]).reshape(xx.shape)
    ax.contourf(xx, yy, zones, alpha=0.25, cmap="tab10")
    ax.contour(xx, yy, zones, colors="#e8f0e7", linewidths=0.6)
    ax.scatter(X[:, 0], X[:, 1], s=2, color="#9aafa0")
    c = model.cluster_centers_
    ax.scatter(c[:, 0], c[:, 1], marker="X", s=90, color="#ff8fab", edgecolors="black", zorder=3)
    ax.set_title(title); ax.set_xlabel("x1"); ax.set_ylabel("x2")

k = 5
kmeans = KMeans(n_clusters=k, init="random", n_init=10, random_state=42)   # 10 стартів, лишається найкращий
y_pred = kmeans.fit_predict(X)                             # номер кластера для кожної точки

fig, (left, right) = plt.subplots(1, 2, figsize=(9.6, 3.8))
left.scatter(X[:, 0], X[:, 1], s=2, color="#7ec8ff")
left.set_title("Дані без міток: видно 5 згустків"); left.set_xlabel("x1"); left.set_ylabel("x2")
plot_regions(kmeans, X, right, "Межі кластерів k-means (діаграма Вороного)")
fig.tight_layout()
plt.show()

print("перші мітки:", y_pred[:8], "| це той самий масив, що labels_:", y_pred is kmeans.labels_)
print("центроїди:")
print(kmeans.cluster_centers_.round(2))

print("нові точки -> кластери:", kmeans.predict(X_new))
print("відстані нових точок до 5 центроїдів (transform):")

Кількість кластерів k треба задати самому. Тут очевидно, що k = 5, але загалом це непросто.

Мітка в кластеризації — це номер кластера, який алгоритм призначив прикладу. Не плутайте з міткою класу в класифікації: там це ціль, а тут — результат. Після навчання мітки лежать у labels_, знайдені центроїди — у cluster_centers_.

Нові приклади легко віднести до кластера з найближчим центроїдом — метод predict.

Діаграма Вороного. Якщо намалювати межі рішень, вийде розбиття площини на області, де найближчим є той чи інший центроїд. Більшість прикладів потрапили куди слід, але біля меж є спірні. k-means погано поводиться, коли згустки мають дуже різні діаметри: для нього важить лише відстань до центроїда.

Жорстка і мʼяка кластеризація. Призначити кожному прикладу один кластер — жорстка кластеризація. Іноді корисніше дати оцінку для кожного кластера — мʼяка. Метод transform повертає відстань від прикладу до кожного центроїда: у виводі перша нова точка на відстані 0.33 від свого центроїда і 2.8–2.9 від трьох інших. Якщо так перетворити багатовимірний набір, вийде набір із k ознак — це ефективний нелінійний спосіб знизити розмірність. Або ці відстані можна додати як ознаки для іншої моделі.

За Жероном · як працює алгоритм k-means

книжка

Припустімо, центроїди відомі. Тоді розставити мітки легко: кожному прикладу — кластер із найближчим центроїдом.

І навпаки: якби були відомі мітки, центроїди знайти легко — це середнє прикладів кожного кластера. Але не відомо ні те, ні інше. Тому починають із випадкових центроїдів (наприклад, беруть k випадкових прикладів із даних), а далі чергують: розставити мітки, оновити центроїди, знову мітки, знову центроїди — доки центроїди не перестануть рухатись.

Три перші ітерації k-means

Кружечок — де центроїд був, хрестик — куди перейшов; колір точок — поточні мітки. У книжці цьому відповідає рис. 8-4. Графік побудовано кодом нижче, а не взято з книжки.

Показати графік

Запустіть код — отримаєте той самий рисунок і числа під ним.

import numpy as np
import matplotlib.pyplot as plt
from sklearn.cluster import KMeans
from sklearn.datasets import make_blobs

centers = np.array([[0.2, 2.3], [-1.5, 2.3], [-2.8, 1.8], [-2.8, 2.8], [-2.8, 1.3]])
spread = np.array([0.4, 0.3, 0.1, 0.1, 0.1])
X, y = make_blobs(n_samples=2000, centers=centers, cluster_std=spread, random_state=7)   # y не використовуємо

rng = np.random.default_rng(5)
centroids = X[rng.choice(len(X), size=5, replace=False)]   # старт: 5 випадкових точок із даних

fig, axes = plt.subplots(1, 3, figsize=(10.2, 3.5), sharex=True, sharey=True)
for step, ax in enumerate(axes, start=1):
    dist = np.linalg.norm(X[:, None, :] - centroids[None, :, :], axis=2)
    labels = dist.argmin(axis=1)                           # 1. кожну точку — до найближчого центроїда
    new_centroids = np.array([X[labels == j].mean(axis=0) for j in range(5)])   # 2. центроїд — у середнє свого кластера
    inertia = (dist.min(axis=1) ** 2).sum()
    ax.scatter(X[:, 0], X[:, 1], s=2, c=labels, cmap="tab10")
    ax.scatter(centroids[:, 0], centroids[:, 1], marker="o", s=70, facecolors="none", edgecolors="#e8f0e7", linewidths=1.5)
    ax.scatter(new_centroids[:, 0], new_centroids[:, 1], marker="X", s=90, color="#ff8fab", edgecolors="black")
    for a, b in zip(centroids, new_centroids):
        ax.plot([a[0], b[0]], [a[1], b[1]], color="#e8f0e7", linewidth=1)
    ax.set_title(f"Ітерація {step}")
    print(f"ітерація {step}: inertia {inertia:8.1f}, центроїди зсунулись у середньому на {np.linalg.norm(new_centroids - centroids, axis=1).mean():.3f}")
    centroids = new_centroids
fig.tight_layout()
plt.show()

for step in range(4, 100):                                 # продовжуємо без малюнків, доки центроїди рухаються
    labels = np.linalg.norm(X[:, None, :] - centroids[None, :, :], axis=2).argmin(axis=1)
    new_centroids = np.array([X[labels == j].mean(axis=0) for j in range(5)])
    if np.allclose(new_centroids, centroids):
        break
    centroids = new_centroids
final = (np.linalg.norm(X - centroids[labels], axis=1) ** 2).sum()
print(f"центроїди перестали рухатись на ітерації {step}, inertia {final:.1f}")
# -> ітерація 1: inertia    573.3, центроїди зсунулись у середньому на 0.164
# -> ітерація 2: inertia    355.5, центроїди зсунулись у середньому на 0.079
# -> ітерація 3: inertia    288.0, центроїди зсунулись у середньому на 0.082
# -> центроїди перестали рухатись на ітерації 7, inertia 236.9

Алгоритм гарантовано зупиняється за скінченну кількість кроків, зазвичай невелику. Причина: середній квадрат відстані від прикладів до найближчих центроїдів на кожному кроці може лише зменшуватись, а відʼємним бути не може.

Примітка з книжки · складність

Обчислювальна складність загалом лінійна за кількістю прикладів m, кластерів k і вимірів n. Але лише коли дані мають кластерну будову. Якщо ні, у найгіршому випадку складність може зростати експоненційно з кількістю прикладів. На практиці це буває рідко, і k-means — один із найшвидших алгоритмів кластеризації.

У нашому запуску inertia падає з 573 до 288 за три ітерації, а зупиняється алгоритм на сьомій зі значенням 236.9. Це гірше за найкращі 211.6 — і це тема наступного блоку.

За Жероном · невдалий старт та ініціалізація центроїдів

книжка

Алгоритм гарантовано зійдеться, але не обовʼязково до правильного розвʼязку: він може зупинитись у локальному оптимумі. Це залежить від стартових центроїдів.

Найкращий і найгірший із 20 запусків з випадковим стартом

Ліворуч кожен згусток має свій центроїд. Праворуч два центроїди ділять один малий згусток, а два згустки зліплено в один кластер. У книжці цьому відповідає рис. 8-5. Графік побудовано кодом нижче, а не взято з книжки.

X, y = make_blobs(n_samples=2000, centers=centers, cluster_std=spread, random_state=7)   # y не використовуємо

def plot_regions(model, X, ax, title):

    zones = model.predict(np.c_[xx.ravel(), yy.ravel()]).reshape(xx.shape)
    ax.contourf(xx, yy, zones, alpha=0.25, cmap="tab10")

    ax.set_title(title); ax.set_xlabel("x1"); ax.set_ylabel("x2")

runs = [KMeans(n_clusters=5, init="random", n_init=1, random_state=seed).fit(X) for seed in range(20)]
runs.sort(key=lambda m: m.inertia_)                        # 20 запусків з різним випадковим стартом
best, worst = runs[0], runs[-1]

fig, (left, right) = plt.subplots(1, 2, figsize=(9.6, 3.8))
plot_regions(best, X, left, f"Вдалий старт · inertia {best.inertia_:.1f}")
plot_regions(worst, X, right, f"Невдалий старт · inertia {worst.inertia_:.1f}")
fig.tight_layout()
plt.show()

print("inertia 20 запусків:", [round(m.inertia_) for m in runs])
print("n_init=10 лишає найкращий із 10:", round(KMeans(n_clusters=5, init="random", n_init=10, random_state=42).fit(X).inertia_, 1))
print("k-means++ з одного запуску:", round(KMeans(n_clusters=5, init="k-means++", n_init=1, random_state=42).fit(X).inertia_, 1))

# -> n_init=10 лишає найкращий із 10: 211.6
# -> k-means++ з одного запуску: 224.1

Книжка показує три способи зменшити цей ризик.

1. Задати старт власноруч. Якщо приблизно відомо, де мають бути центроїди, у параметр init передають масив із ними.

2. Запустити кілька разів і лишити найкраще. Кількість запусків задає n_init. Найкращий розвʼязок вибирають за метрикою, яка називається inertia: сума квадратів відстаней від кожного прикладу до найближчого центроїда. У книжці вона дорівнює приблизно 219.6 і 600.4 для двох невдалих розвʼязків і 211.6 для вдалого. Значення доступне в inertia_. Метод score() повертає inertia зі знаком мінус, бо в scikit-learn більша оцінка завжди має означати кращу модель.

3. k-means++. Важливе вдосконалення, запропоноване 2006 року Девідом Артуром і Сергієм Васильвицьким: розумніший старт, який намагається вибирати центроїди далеко один від одного.

  1. Перший центроїд — приклад, вибраний з даних рівномірно випадково.
  2. Кожен наступний центроїд — приклад, вибраний з імовірністю, пропорційною D(x)², де D(x) — відстань від прикладу до найближчого вже вибраного центроїда. Далекі приклади вибираються значно частіше.
  3. Повторювати, доки не вибрано всі k центроїдів.

Додаткові обчислення на старті окупаються: запускати алгоритм доводиться значно менше разів. У KMeans це поведінка за замовчуванням (точніше, «жадібний» варіант k-means++, який на кожному кроці пробує кілька кандидатів і бере найкращого); n_init при цьому за замовчуванням дорівнює 1.

Ще два вдосконалення з книжки — для великих наборів даних.

Прискорений k-means. 2003 року Чарльз Елкан запропонував уникати багатьох зайвих обчислень відстаней. import matplotlib.pyplot as plt
from sklearn.cluster import KMeans
from sklearn.datasets import make_blobs

centers = np.array([[0.2, 2.3], [-1.5, 2.3], [-2.8, 1.8], [-2.8, 2.8], [-2.8, 1.3]])

Лікоть. Inertia дуже швидко падає до k = 4, а далі — значно повільніше. Крива схожа на руку з ліктем на k = 4. Не знаючи більшого, можна було б вибрати 4: менше значення різко гірше, а більше мало що дає — можливо, ми просто ділимо добрі кластери навпіл. Метод доволі грубий.

Silhouette score точніший, але дорожчий в обчисленні. Це середній коефіцієнт силуету по всіх прикладах. Коефіцієнт одного прикладу — (b − a) / max(a, b), де a — середня відстань до інших прикладів того самого кластера, b — середня відстань до прикладів найближчого чужого кластера. Значення лежить між −1 і +1. Близько до +1: приклад глибоко у своєму кластері й далеко від інших. Близько до 0: на межі кластерів. Близько до −1: можливо, приклад віднесено не до того кластера.

Графік підтверджує, що k = 4 — дуже добрий вибір, але показує й те, чого не видно з inertia: k = 5 теж цілком добрий і значно кращий за 6 чи 7.

Діаграма силуетів (рис. 8-9) ще інформативніша: коефіцієнти всіх прикладів, згруповані за кластером і відсортовані. Кожен кластер виглядає як лезо ножа: висота — кількість прикладів, ширина — коефіцієнти (ширше — краще). Якщо в кластері більшість прикладів не дотягує до середньої лінії, кластер поганий: його приклади надто близько до інших кластерів. Для k = 4 один кластер дуже великий; для k = 5 усі приблизно однакові. Тому, хоча загальна оцінка для k = 4 трохи вища, розумно взяти k = 5.

K-means: центри і призначення точок

сьогодні

K — скільки груп, це наше число. Алгоритм тримає K центрів. Кожну точку віддає найближчому центру, потім центр стає середнім своїх точок. Так повторюють, доки призначення не перестануть змінюватись.

На старті центри ставлять у дані або випадково. Інший старт може дати інші групи.

Відстань зазвичай квадрат евклідової. Тому стовпці знову вирівнюють за масштабом до старту.

K не випливає з точок. Чотири хмари на малюнку видно оком. Алгоритм про чотири не здогадується, доки ми не скажемо K=4.

Що перераховується

Яка точка якому центру належить і де стоїть центр.

Коли зупиняється

Коли точки більше не стрибають між центрами.

from __future__ import annotations

try:
    import random

    points = [0.1, 0.0, 0.2, 3.1, 2.9, 3.0]

    def labels_for(seed: int) -> list[int]:
        random.seed(seed)
        centers = [random.choice(points), random.choice(points)]
        return [0 if abs(p - centers[0]) <= abs(p - centers[1]) else 1 for p in points]

    runs = [labels_for(s) for s in range(8)]
    agree = sum(a == b for a, b in zip(runs[0], runs[1])) / len(points)
    sizes = [runs[0].count(0), runs[0].count(1)]
    print('seed_agree', round(agree, 3), 'sizes', sizes)
    assert min(sizes) >= 0 and 0 <= agree <= 1
except ModuleNotFoundError as exc:
    print('skip_missing_dep', getattr(exc, 'name', None) or exc)

Кластер — група схожих рядків без готової мітки. k-means вимагає кількість груп наперед. DBSCAN збирає щільні області і лишає рідкі точки осторонь.

k=3 означає рівно три центри. Кожен рядок іде до найближчого центру. Центр потім стає середнім своїх рядків. Кількість 3 задаємо ми, координати центрів зрушує метод.
