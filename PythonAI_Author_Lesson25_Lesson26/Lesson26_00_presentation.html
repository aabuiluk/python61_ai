Токенізація, лематизація, стемінг і стоп-слова

сьогодні

Токен — шматок тексту, з яким далі рахують. Лема зводить слово до словникової форми. Стем грубо відрізає хвіст. Стоп-слово — часте слово, яке іноді викидають.

«Коти, котів, кіт» для лічильника можуть бути трьома різними токенами або однією лемою. Що зводити, вирішуємо ми до підрахунку частот.

Стемінг не перевіряє словник. Він ріже закінчення за правилом і може зламати слово. Лема повільніша і ближча до форми зі словника.

Стоп-слова на кшталт «і», «в», «на» є майже в кожному реченні. Якщо задача про тему, їх прибирають. Якщо задача про стиль, їх якраз лишають.

tokens = text.lower().split()

Що задаємо ми

Як різати рядок, чи зводити до леми, який список стоп-слів.

Що виходить

Список токенів і лічильник. Модель бачить уже цей список, не сирий абзац.

Пастка

Викинути стоп-слова в задачі, де саме вони відрізняють тексти.

Приклад · від одного рядка до списку токенів

теорія

Глибина пояснення

Почнемо з одного короткого відгуку. Саме на одному рядку найкраще видно, що роблять lower() і грубе прибирання пунктуації.

Почнемо з одного короткого відгуку. Саме на одному рядку найкраще видно, що роблять lower() і грубе прибирання пунктуації.

text = "The app is fast. Support replied within an hour!"
clean = text.lower()
for ch in ".!,?;:":
    clean = clean.replace(ch, " ")
tokens = [w for w in clean.split() if w]
print(tokens)
# -> ['the', 'app', 'is', 'fast', 'support', 'replied', 'within', 'an', 'hour']
Зверніть увагу

Навіть цей грубий крок уже робить текст придатним для підрахунків. Пізніше NLTK замінить лише частину ручної роботи.

теорія

Глибина пояснення

Тепер той самий текст обробляємо офіційним API аркуша: nltk.word_tokenize. Якщо ресурсу punkt немає, fallback на split() дає нам робочий стенд замість зірваної пари.

Тепер той самий текст обробляємо офіційним API аркуша: nltk.word_tokenize. Якщо ресурсу punkt немає, fallback на split() дає нам робочий стенд замість зірваної пари.

clean = "the app is fast support replied within an hour"
try:
    from nltk.tokenize import word_tokenize
    tokens = word_tokenize(clean)
except (ImportError, LookupError, OSError):
    tokens = clean.split()
print(len(tokens), tokens[:8])
# -> 9 ['the', 'app', 'is', 'fast', 'support', 'replied', 'within', 'an']
Зверніть увагу

LookupError тут означає відсутній ресурс корпусу, а не «помилку Python». Логіку обробки це не скасовує.

Лема і стем: нормалізація з різною ціною

теорія

Глибина пояснення

Коли одне й те саме слово має кілька форм, частоти розмазуються. Нормалізація збирає ці форми ближче одна до одної.

Коли одне й те саме слово має кілька форм, частоти розмазуються. Нормалізація збирає ці форми ближче одна до одної.

Лема намагається повернути словникову форму слова. Стем грубо зрізає суфікси. Лема читабельніша, стем дешевший і грубіший.

Коротко

На звіті для людини леми зазвичай виглядають охайніше. Для швидкого грубого фільтра інколи вистачає стема.

Приклад · слово / лема / стем

теорія

Глибина пояснення

Порівняти лему і стем краще в таблиці, а не в абстрактному описі. Візьмемо слова, де різниця справді помітна.

Порівняти лему і стем краще в таблиці, а не в абстрактному описі. Візьмемо слова, де різниця справді помітна.

from nltk.stem import PorterStemmer, WordNetLemmatizer

wn = WordNetLemmatizer()
ps = PorterStemmer()
for word in ["running", "studies", "better"]:
    print(word, wn.lemmatize(word), ps.stem(word))
# -> running running run
# -> studies study studi
# -> better better better
Зверніть увагу

Слово better лишається better, бо без POS WordNet вважає його іменником. Це корисно проговорити вголос.

Навіщо цей шар

Новий акцент: Український апостроф і NFC/NFD ламають токени ще до NLTK.

Поки ви порівнюєте лему і стем, один і той самий рядок «зв'язок» може дати різні токени: літера плюс комбінуючий знак проти однієї NFC-літери, апостроф U+0027 проти U+2019. Спочатку зафіксуйте контракт нормалізації.

Лекція вже дає пайплайн clean → tokenize → lemma/stem → stopwords → CSV і fallback на split(); movie_reviews лише згадується, без Unicode-контракту.

Поняття

Контракт токенізатора — це не «викликати word_tokenize». Це явний порядок: Unicode normalize (зазвичай NFC) → уніфікація апострофа/дефіса → токени → те саме на train і на prod. spaCy і NLTK розійдуться на скороченнях і пунктуації; розбіжність треба виміряти, а не сперечатися «хто правильний».

"""Runnable demo for pair 26: Український апостроф і NFC/NFD ламають токени ще до NLTK."""

from __future__ import annotations

try:
    import unicodedata

    def tokenize_contract(text: str) -> list[str]:
        text = unicodedata.normalize('NFC', text.replace('\u2019', "'"))
        return [tok for tok in text.replace('.', ' .').split() if tok]

    nfc = unicodedata.normalize('NFC', 'їжак')
    nfd = unicodedata.normalize('NFD', 'їжак')
    print('same_str', nfc == nfd, 'nfd_extra', len(nfd) - len(nfc))
    a = tokenize_contract("Це зв'язок.")
    b = tokenize_contract('Це зв\u2019язок.')
    assert a == b, (a, b)
    print(a)
except ModuleNotFoundError as exc:
    print('skip_missing_dep', getattr(exc, 'name', None) or exc)

Глибина пояснення

Текст для моделі — послідовність номерів, не рядок символів. Токен — шматок, якому дали номер у словнику.

Слово «кіт» може стати одним номером або кількома, якщо словник ріже на частини. Довжина входу — кількість токенів, не кількість літер.

Корпус — багато таких послідовностей. Модель бачить номери і сусідів, не «сенс речення» окремим полем.
