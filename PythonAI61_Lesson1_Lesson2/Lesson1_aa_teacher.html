Історія розвитку штучного інтелекту

основний блок15 хв

ШІ — не «нова фішка 2023», а довга інженерна історія з циклами очікувань і розчарувань.

  • 1950 — Алан Тюрінг: тест Тюрінга як операційне питання «чи може машина мислити?».
  • 1956 — Дартмутський семінар: народження терміна Artificial Intelligence.
  • 1960–70 — символьні системи, експертні правила; обмеження ручного знання.
  • 1980-ті — експертні системи в бізнесі; далі — «зима ШІ» через вартість і крихкість правил.
  • 1990–2010 — статистичний ML, SVM, random forest; перемога data-driven підходу.
  • 2012+ — deep learning (ImageNet), GPU, великі датасети.
  • 2017+ — Transformers; 2022+ — масовий Generative AI / LLM.
Як вести: намалюйте на дошці хвилю hype → winter → revival. Попросіть студентів назвати продукт, яким вони користуються щодня і який «тихо» містить ML.
Додатковий матеріал

Чому були «зими ШІ»? Занадто сильні обіцянки + брак даних/обчислень + крихкі rule-based системи. Сучасний бум тримається на трьох ніжках: дані, compute, алгоритми представлення (representation learning).

Корисна рамка для пари: символьний ШІ (правила) vs статистичний ШІ (навчання з даних) vs генеративний ШІ (моделі розподілу даних / мови).

# Міні-ілюстрація: "правило" vs "навчання з даних"
# Rule-based: людина кодує логіку
def is_spam_rule(text: str) -> bool:
    keywords = ["виграш", "безкоштовно", "клікни"}
    return any(k in text.lower() for k in keywords)

# ML-підхід (ідея): модель оцінює ймовірність за ознаками
# P(spam | features) — це вже задача класифікації
print(is_spam_rule("Клікни і отримай виграш!"))

Додатковий матеріал

Data Science pipeline, який повторюватимемо весь курс:

  1. Бізнес-питання і критерій успіху
  2. Збір / доступ до даних
  3. Очищення і EDA
  4. Ознаки (feature engineering)
  5. Модель / baseline
  6. Валідація і метрики
  7. Впровадження, моніторинг, етика

Наголосіть: модель без метрики і без розуміння даних — демо, не продукт.

Види алгоритмів навчання

основний блок20 хв

Ключ до класифікації методів — який сигнал навчання ми маємо.

  • Supervised (з учителем) — є цільова змінна y. Приклади: ціна житла, spam/not-spam, діагноз.
  • Unsupervised (без учителя) — лише X. Приклади: сегменти клієнтів, аномалії, зменшення розмірності.
  • Reinforcement (з підкріпленням) — агент діє в середовищі, отримує нагороду. Приклади: ігри, рекомендації з feedback loop, роботи.

Усередині supervised майже завжди дві сімʼї:

  • Регресія — неперервний y (ціна, температура, LTV).
  • Класифікація — дискретний y (клас, ймовірність класу).
from dataclasses import dataclass

@dataclass
class MLTask:
    name: str
    has_target: bool
    target_type: str | None  # "numeric" | "categorical" | None
    feedback: str            # "labels" | "structure" | "reward"

examples = [
    MLTask("Ціна квартири", True, "numeric", "labels"),          # supervised regression
    MLTask("Spam-фільтр", True, "categorical", "labels"),        # supervised classification
    MLTask("Сегменти клієнтів", False, None, "structure"),       # unsupervised clustering
    MLTask("Торговий бот", False, None, "reward"),               # reinforcement
]

for t in examples:
    if t.feedback == "labels" and t.target_type == "numeric":
        kind = "supervised / regression"
    elif t.feedback == "labels":
        kind = "supervised / classification"
    elif t.feedback == "structure":
        kind = "unsupervised"
    else:
        kind = "reinforcement"
    print(f"{t.name:20} -> {kind}")
Додатковий матеріал

Сірі зони, які варто згадати (без глибокого занурення):

  • Semi-supervised — мало міток, багато сирих даних.
  • Self-supervised — мітки створюються з самих даних (маски в LLM, contrastive learning).
  • Imitation learning — на межі supervised і RL.
Типова помилка студентів: називати кластеризацію «класифікацією». Класифікація потребує заздалегідь відомих класів-міток.

Глибоко: цикл ML-продукту

основний блок8 хв

На рівні senior-практики ML рідко починається з вибору моделі. Типовий цикл:

  1. Decision framing — яке рішення людини/процесу замінюємо або підтримуємо?
  2. Label design — як визначити y так, щоб мітка була доступною і чесною?
  3. Baseline — правило/евристика/константа mean перед ML.
  4. Offline evaluation — метрики на holdout / time split.
  5. Online / human review — чи реально стало краще в процесі?
  6. Monitoring — drift даних, деградація якості, вартість помилок.
Попросіть студентів для кейсу «рекомендації курсів» пройти пункти 1–3 усно за 4 хвилини.
Додатковий матеріал

Anti-patterns, які варто назвати вже на 1-й парі:

  • оптимізувати accuracy при сильному дисбалансі класів;
  • тестувати на тих самих даних, що й train;
  • ігнорувати вартість false positive vs false negative;
  • плутати демо на ноутбуці з production-системою.
