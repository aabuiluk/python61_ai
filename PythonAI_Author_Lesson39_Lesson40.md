```python
    {"id": "b02", "title": "Практика Python", "price": 450, "topic": "python"},

SOURCE = "[S1] Книга b01 коштує 320 грн. [S2] Повернення можливе протягом 14 днів."
def validate(raw):
    try:
        obj = json.loads(raw)
    except (json.JSONDecodeError, TypeError):
        return False
    if not isinstance(obj, dict) or set(obj) != {"book_id", "price"}:
        return False
    return any(obj["book_id"] == b["id"] and type(obj["price"]) is int
               and obj["price"] == b["price"] for b in CATALOG)
def chunks(text, size=12, overlap=3):
    if type(size) is not int or type(overlap) is not int or not 0 <= overlap < size:
        raise ValueError("Потрібно: size > overlap >= 0")
    words = text.split()
    result = []
    start = 0
    while start < len(words):
        result.append(" ".join(words[start:start+size]))
        if start+size >= len(words):
            break
        start += size-overlap
    return result
```

**Факт. Zero-shot задає правило без прикладів, а few-shot додає приклади потрібного перетворення.**

Слово shot означає приклад «вхід → правильний вихід» усередині промпту, а не кількість
спроб запуску. Zero-shot: «Позначте відгук як positive, negative або mixed». Few-shot додає
приклади перед новим відгуком. Вага моделі від цього не оновлюється: це навчання за контекстом
запиту (in-context learning), а не fine-tuning.

Візьміть відгук «Доставка швидка, але обкладинка пошкоджена». Без категорії mixed модель
може вибрати один бік. Приклади допомагають показати межу, але не виправлять суперечливу
інструкцію. У прикладі нижче створюємо два промпти для того самого відгуку. Ми ще не викликаємо LLM.

Для живого порівняння запустіть zero-shot у новому чаті Gemini або ChatGPT, збережіть відповідь.
У другому новому чаті запустіть few-shot. Не додавайте правильну відповідь для тестового відгуку
в приклади: інакше ви підказали розв’язок. Перевірте результат вручну за однаковою рубрикою:
positive — тільки позитив, negative — тільки негатив, mixed — обидва. Один запуск не доводить,
що few-shot завжди кращий. Приклади мають охоплювати межові випадки, а не повторювати один клас.

### Приклад · основний код


```python
review = "Доставка швидка, але обкладинка пошкоджена"
instruction = "Класифікуйте відгук: positive, negative або mixed. Поверніть тільки мітку."
zero_prompt = instruction + "\nВідгук: " + review
few_prompt = instruction + "\nПриклади: Чудова книга → positive; Книга порвана → negative; Цікава, але порвана → mixed.\nВідгук: " + review
print(zero_prompt)
print(few_prompt)
```

```text

Відгук: Доставка швидка, але обкладинка пошкоджена
```

# Блок 5. 39 · Self-Consistency: кілька спроб та агрегація

**60–70 хв.**

**Факт. Self-Consistency агрегує відповіді кількох різних спроб; більшість не гарантує істини.**

В оригінальному підході генерують різні шляхи розв’язання, витягують кінцеві відповіді
та обирають найузгодженішу. У навчальній версії зберігаємо п'ять окремих результатів і рахуємо
частоти. Це відрізняється від прохання в одному повідомленні «подумай п'ятьма способами»:
таке повідомлення не забезпечує п'ять незалежних запусків. Навіть нові чати не роблять
виходи статистично незалежними: та сама модель може повторювати одну помилку.

Спершу нормалізуйте відповіді: "1170 грн" і "1170" мають дати одне число. Не порівнюйте
неочищені рядки. Окремо відкиньте непридатні відповіді та повідомте їхню кількість.
При нічиїй не обирайте перший елемент випадково: поверніть статус tie або відмову.
Після голосування перевірте результат Python, каталогом чи іншим зовнішнім джерелом.

Для живої роботи повторіть один промпт у п'яти нових чатах Gemini АБО ChatGPT, не змішуючи
провайдерів у межах одного досліду. Збережіть усі відповіді, модель і дату. При вичерпанні
безкоштовного ліміту використовуйте fixtures та явно назвіть дослід симуляцією агрегації.

# Блок 7. 39.3 · ToT: альтернативи, критерій, вибір

**85–105 хв.**

**Факт. У розгалуженому пошуку оцінюють проміжні варіанти й продовжують кілька гілок.**

Tree-of-Thought (ToT) працює з деревом можливих продовжень: generate → evaluate →
select → expand. Коли напрям виявляється невдалим, пошук може перейти до іншої збереженої
гілки. Оцінка може бути евристикою, перевіркою коду або оцінкою моделі; самооцінка LLM
не є незалежною гарантією правильності. Ширина пошуку та глибина збільшують кількість викликів.

Задача: обрати дві різні книги. На першому рівні є A, B, C. На другому додаємо другу
книгу, обчислюємо сумарну ціну й бал та відкидаємо перевищення бюджету. Дорогий перший
кандидат може залишити надто мало бюджету для другої книги: жадібний вибір першого
найбільшого score програє пошуку кількох гілок. Код зберігає журнал усіх розширень,
тому можна показати не тільки переможця, а й причину відмови від альтернатив.

Це точна навчальна аналогія дерева пошуку з ручними балами, не реалізація оригінального
LLM-ToT. Для живого варіанта в Gemini або ChatGPT надішліть запит створити перші кандидати,
оцініть ціни кодом, передайте тільки допустимі гілки назад і попросіть розширити другий рівень.
Так дані самооцінки та зовнішня арифметична перевірка лишаються розділеними.
У промпті просимо короткі варіанти й оцінки, а не приховану внутрішню трасу мислення.

### Приклад · основний код


```python
# Два рівні пошуку: перша книга -> друга книга; оцінка після кожного розширення.
pool = [{"id":"A","price":320,"score":2}, {"id":"B","price":450,"score":5}, {"id":"C","price":390,"score":3}]
frontier = [{"ids":[],"cost":0,"score":0}]
trace = []
for depth in (1,2):
    expanded = []
    for node in frontier:
        for item in pool:
            if item["id"] in node["ids"]:
                continue
            child = {"ids":node["ids"]+[item["id"]],"cost":node["cost"]+item["price"],"score":node["score"]+item["score"]}
            accepted = child["cost"] <= 750
            trace.append({"depth":depth,**child,"accepted":accepted})
            if accepted:
                expanded.append(child)
    frontier = expanded  # зберігаємо всі допустимі гілки, без жадібного обрізання
best = min(frontier,key=lambda n:(-n["score"],n["cost"],n["ids"])) if frontier else None
print("Найкраща пара:",best)
print("Перевірено гілок:",len(trace),"; відкинуто:",sum(not x["accepted"] for x in trace))
```

```text
Перевірено гілок: 9 ; відкинуто: 4
```

# Блок 12. 40.2 · Цитата, джерело і право відмовитись

**160–175 хв.**

**Факт. Посилання має вести до тексту, який справді підтримує відповідь.**

Grounding означає прив'язування відповіді до наданих джерел. Саме слово «цитуй» не захищає
від вигаданої цитати. Перевірте: id джерела відомий, цитата дослівно міститься в ньому,
а відповідь підтримується цитатою. Останню перевірку в загальному випадку не можна
замінити простим пошуком підрядка: «320» і «не 320» мають різний сенс.

У прикладі перевіримо точний вузький контракт із ціною. Для іншого питання — окремі правила
або ручна перевірка. Коли в тексті немає автора книги, answer=null — правильна відмова.

Поверніть answer, source_id, quote; quote дослівна. Якщо немає факту — три null».

**Контрольне переформулювання:** замість «Які у вас правила повернення?» поставте
«Витягніть тільки кількість днів із S2; якщо її немає, answer=null». Це звужує задачу
до перевірюваного факту, але не гарантує усунення галюцинацій. Послідовність перевірки:
JSON читається → ключі й типи правильні → id джерела існує → цитата дослівна → число
відповідає цитаті → відповідь стосується питання. Не повторюйте запит до отримання
приємного результату: це приховує невдалі спроби. Кожне переформулювання має власну версію
